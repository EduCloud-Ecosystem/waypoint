The idea

One front door for every app we publish

Instead of hand-building servers per app, every app rides the same stack. Hosts an R/Shiny, Python, or static report tenant the same way, with sign-in handled centrally.

R / Shiny

Interactive dashboards

Rocker r2u base image, packages baked in, WebSockets through the proxy.

Python

Dash, Streamlit, FastAPI

Slim Python image with a per-framework start command and persistent data volumes.

Static

Self-contained reports

Plain HTML served from a small static container at its own subdomain.

The publishing contract
01
A repo
Self-contained, relative paths.
02
An environment
Package list or a Dockerfile.
03
Secrets by name
Values entered in Coolify, never in the repo.
04
A destination
Subdomain, sensitivity, owner.

Final next steps

One approval away from a live platform

1

Approve the server budget

The only blocker. DigitalOcean droplet already chosen and sized. Nothing else depends on being done first.

2

Provision and secure (Phases 1 to 2)

Stand up the VM, install Coolify, lock down the dashboard.

3

Transplant the proven stack (Phase 3)

Keycloak realm and the auth gate move over as configuration, not new integration. This was the hard part and it is done.

4

Onboard the real apps (Phases 4 to 7)

R, Python, and static tenants on their subdomains, gated by sensitivity, auth matrix verified.

5

Backups, tested restore, launch (Phases 8 to 9)

Verify, back up, do one real restore, then share URLs and the runbook with the team.

Bottom line

The architecture and the riskiest piece, authentication, are validated. We are one budget approval away from a live platform.

  • The full stack runs and the auth round trip passes locally.
  • Server-side work is transplanting proven pieces, not first-time integration.
